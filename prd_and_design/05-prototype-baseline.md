# 原型设计基线

> 本文记录 2026-09-11 至 2026-09-14 的 Hook-first V1/V2 历史评审。用户于 2026-09-24 改用 Git 历史管理旧原型，旧目录已从当前工作树移除；现在的 `prototype-v1` 是产品 V1.0 的 OTel + Transcript 原型，不能用本文的旧路径或运行命令解释其设计。当前规格见 [V1.0 原型规格](./17-v1-prototype-spec.md)。

## 基线信息

- 版本：V1。
- 冻结日期：2026-09-11。
- 当时源码目录：`prototype-v1`；旧版本从 Git 历史检出。
- 定位：产品需求、信息架构、视觉层级和交互行为的可运行参考，不是线上数据采集实现。
- 数据：仅使用人工构造的 Mock 数据，不读取本机 Codex 数据，不发送 OTLP，不写入数据库。

## 已确认范围

V1 包含分析总览、一轮对话 Trace 详情、当前会话和采集状态四类界面，确认了以下关键设计：

- 主统计对象为执行轮次，搜索项拆分为会话 ID、会话标题和用户问题。
- 所有核心指标提供分子、分母、排除项和数据来源等口径说明。
- 总览以跨轮次的“异常耗时贡献”表达瓶颈，不以每轮最大耗时类别替代异常判断。
- Trace 通过 JSONL 行为层和 OTel 性能层共同展示“做了什么”和“时间花在哪里”。
- 点击 JSONL 节点或当前会话事件可以检查输入、输出、解析字段和原始数据。
- Trace 保留紧凑的本轮耗时摘要，不使用面向用户的独立“关键路径构成”卡片。
- 自动诊断首版采用确定性规则引擎，不调用模型；证据不足时不生成确定结论。
- 数据完整度、关联可信度和采集健康是三个独立概念，各自展示判定口径。
- 采集状态包含健康证据、关联明细分页、增量补扫说明和 OTLP/HTTP 接收器健康指标。

完整需求和验收条件见 [产品需求](./01-product-requirements.md) 与 [H5 原型规格](./04-prototype-spec.md)。

## 参考顺序

1. 产品需求决定产品语义、指标口径和数据边界。
2. V1 冻结原型决定已确认的页面结构、视觉层级和交互方式。
3. 数据与关联模型决定 Hook、JSONL、OTel 及跨源关联规则。
4. 技术设计决定工程结构和实现方式。

原型不是需求的唯一来源：不能仅凭界面像素推导缺失的业务口径，也不能用实现便利改变 PRD。若文档与原型冲突，应先明确并修正文档，而不是默默选择其中一个。

## 冻结与变更规则

- 当时通过独立目录冻结 V1/V2；现行规则改为同一需求版本直接迭代相应原型目录，旧评审状态使用 Git 历史追溯。
- 正式前端功能仍只在 `frontend` 实现；原型不得提交依赖、构建产物、本机配置、真实会话或凭据。

## V2 已确认基线

- 当时源码目录：`prototype-v2`；旧版本从 Git 历史检出。
- 确认日期：2026-09-14。
- V2 从冻结 V1 复制，确认为 Hook-first 设计：Hook 建立骨架，JSONL 补齐内容，OTel 补齐性能；同时包含 transcript/session_meta 健康、UNKNOWN 映射、实时会话和 Trace 三源证据；V1 保持不变。
- V2 仍只使用虚构 Mock 数据，不连接 Codex、不读取 JSONL、不监听 Hook/OTLP、不写数据库。
- V2 已由用户确认，可以开始向 `frontend` 和 `backend` 实现。后续产品语义或交互变化必须建立 V3，不得回写 V1 或已确认的 V2。

## 已知简化

- 所有列表、指标、状态变化和诊断结论均来自前端 Mock 数据。
- 页面导航和状态保存在浏览器内存中，刷新后不保证保留操作现场。
- 时间轴关联、自动诊断和异常贡献使用固定演示样本，不代表采集与计算链路已经实现。
- 不包含后端 API、SQLite、Hook 接收、transcript 内容补齐、OTLP/HTTP 接收器、SSE 或真实权限边界。
- 响应式布局用于能力验证，正式前端仍需补充组件拆分、测试、错误态和可访问性验证。
