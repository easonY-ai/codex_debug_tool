# 原型设计基线

## 基线信息

- 版本：V1。
- 冻结日期：2026-09-11。
- 源码目录：[`./prototype-v1`](./prototype-v1/README.md)。
- 定位：产品需求、信息架构、视觉层级和交互行为的可运行参考，不是线上数据采集实现。
- 数据：仅使用人工构造的 Mock 数据，不读取本机 Codex 数据，不发送 OTLP，不写入数据库。

## 已确认范围

V1 包含分析总览、一轮对话 Trace 详情、当前会话和采集状态四类界面，确认了以下关键设计：

- 主统计对象为执行轮次，搜索项拆分为会话 ID、会话标题和用户问题。
- 所有核心指标提供分子、分母、排除项和数据来源等口径说明。
- 总览以跨轮次的“异常耗时贡献”表达瓶颈，不以每轮最大耗时类别替代异常判断。
- Trace 通过 JSONL 行为层和 OTel 性能层共同展示“做了什么”和“时间花在哪里”。
- 点击 JSONL 节点或当前会话事件可以检查输入、输出、解析字段和原始数据。
- Trace 保留紧凑的本轮耗时摘要，不使用面向用户的独立“关键路径构成”卡片。
- 自动诊断首版采用确定性规则引擎，不调用模型；证据不足时不生成确定结论。
- 数据完整度、关联可信度和采集健康是三个独立概念，各自展示判定口径。
- 采集状态包含健康证据、关联明细分页、增量补扫说明和 OTLP/HTTP 接收器健康指标。

完整需求和验收条件见 [产品需求](./01-product-requirements.md) 与 [H5 原型规格](./04-prototype-spec.md)。

## 参考顺序

1. 产品需求决定产品语义、指标口径和数据边界。
2. V1 冻结原型决定已确认的页面结构、视觉层级和交互方式。
3. 数据与关联模型决定 JSONL、OTel 及跨源关联规则。
4. 技术设计决定工程结构和实现方式。

原型不是需求的唯一来源：不能仅凭界面像素推导缺失的业务口径，也不能用实现便利改变 PRD。若文档与原型冲突，应先明确并修正文档，而不是默默选择其中一个。

## 冻结与变更规则

- `prototype-v1` 视为只读快照，后续功能开发只修改仓库根目录下的 `frontend`。
- 产品语义、指标口径或交互发生变化时，先更新 PRD 和原型规格，再复制出 `prototype-v2` 进行评审。
- 新版本确认后再把差异实现到正式前端；不得覆盖或补写 V1 来伪造历史基线。
- V1 目录不提交 `node_modules`、`dist`、本机配置、真实会话或任何账号凭据。
- Git 提交或版本标签由维护者单独执行；目录冻结本身不隐含已经创建 Git 标签。

## 已知简化

- 所有列表、指标、状态变化和诊断结论均来自前端 Mock 数据。
- 页面导航和状态保存在浏览器内存中，刷新后不保证保留操作现场。
- 时间轴关联、自动诊断和异常贡献使用固定演示样本，不代表采集与计算链路已经实现。
- 不包含后端 API、SQLite、JSONL 周期扫描、OTLP/HTTP 接收器、SSE 或真实权限边界。
- 响应式布局用于能力验证，正式前端仍需补充组件拆分、测试、错误态和可访问性验证。

## 运行与复现

```bash
cd prd_and_design/prototype-v1
npm ci
npm run dev
```

默认访问 `http://127.0.0.1:4173/`。可使用 `npm run build` 验证生产构建。原型与正式前端使用相同默认端口，不应同时启动。
