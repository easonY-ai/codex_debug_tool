# H5 原型规格

## 原型目标

第一阶段验证产品是否能直观表达 Codex 的行为和性能，不验证真实采集能力。原型只使用 Vue 前端和虚构 Mock 数据，不连接本机 Codex、不创建 SQLite、不提供 OTLP 接口。

## 页面结构

### 分析总览

- 主列表的统计对象是执行轮次，并展示每个轮次所属的会话 ID。
- 顶部将会话 ID、会话标题和用户问题拆成独立搜索项，同时提供时间、客户端来源和状态筛选。
- 工作目录和模型不作为首版筛选项，仅在详情原始字段中展示。
- 指标卡展示执行轮次数、总耗时、TTFT、工具耗时和失败率；悬浮指标名称时展示统计对象、分子/分母、排除项和数据来源。
- 总览 TTFT 统计筛选范围内所有成功获得首个可见文本增量的模型请求，而不是每轮次只统计第一次请求。
- 模型请求耗时保持端到端口径，不推测拆分网络耗时和模型处理耗时。
- 趋势图展示总耗时、TTFT 和工具耗时变化。
- 执行轮次列表展示用户问题、所属会话、来源、总耗时、请求 TTFT、诊断摘要和数据完整度。
- 点击执行轮次进入 Trace 详情。

### Trace 详情

- 顶部展示会话和轮次标识、用户问题、状态、来源、总耗时、Token 和数据完整度；模型与工作目录仅在详情原始字段中展示。
- 主区域使用共享横向时间轴。
- Hook 行为层按用户、模型、审批和工具分组；节点身份与生命周期来自 Hook，JSONL 只补充可见正文、工具参数、结果和原文。
- OTel 性能层按 API/传输、推理和工具 Span 分组。
- 支持滚轮或控件缩放、拖动平移、悬停提示和当前时间游标。
- 点击节点后打开统一详情面板；Hook 节点展示生命周期原文、JSONL 内容补齐状态、已有输入/输出和对应 OTel 原文。
- 关联节点只高亮，不合并绘制；低可信度使用虚线或弱化连接。
- 时间轴内部使用依赖关系识别真正延长完成时间的阶段，但不向用户展示“关键路径构成”独立卡片。
- 时间轴附近展示紧凑的本轮耗时摘要；模型请求、工具、审批、本地处理和未归因之和必须等于轮次总耗时，并行区间不得重复累计。

### 实时会话

- 展示当前正在执行和刚完成的会话，以及最后事件时间、当前阶段和已运行时长。
- 支持选中会话查看最新事件流、阶段进度和实时性能摘要。
- 原型使用定时更新的虚构计时器表达实时感，不连接本机 Codex。
- 最新事件列表中的每个事件均可点击，并使用与 Trace 详情一致的检查器展示输入、输出和原始数据。

### 采集状态

- 分别展示 Hook 主骨架接收、Hook 引用的 JSONL 内容补齐、OTLP Logs/Traces/Metrics 和 SQLite 的状态。
- 展示虚构的 Hook 接收进度、已绑定 transcript 内容补齐进度、最近接收时间以及未关联记录数量。
- V2 增加 Hook 接收状态，并说明 Hook 不提供历史重放、部分 hosted tools 不在覆盖范围内。
- V2 增加 `transcript_path` 文件级关联健康卡与明细，覆盖有效、空值、缺失、不可读和越界/符号链接状态。
- transcript 明细展示首行 `session_meta.payload.session_id` 与 Hook `session_id` 的校验结果，并包含元数据缺失、格式不支持和 ID 不一致状态。
- V2 增加按结构指纹去重的 UNKNOWN 列表，以及人工 JSONPath 映射抽屉。抽屉必须提供受限语法示例、实时匹配预览、基数/类型校验和模拟保存反馈。
- V2 明确 `session_id`、Hook `tool_use_id` 和 JSONL `call_id` 的命名空间，不暗示后二者天然相等。
- 支持模拟重试 Hook 已绑定 transcript 的内容补齐，并复制 Hook/OTel 安装检查清单，但不得修改用户配置文件或展示未经验证的 Hook TOML。
- “采集正常”要求 Hook 接收心跳、transcript/session_meta 校验、JSONL 内容补齐、OTLP 接收失败率、接收队列和 SQLite 写入均处于阈值内，并展示每项判定证据。
- 手动重试只针对 Hook 已绑定的 transcript，从持久化字节偏移读取延迟写入或遗漏的新行；必须幂等，不发现独立历史会话，也不能补回 Hook 或 OTel。
- OTLP/HTTP 接收器展示从收到请求到完成解码、校验并加入写入队列的平均、P99、最大处理耗时和非 2xx 失败次数。
- V2 分别展示 Hook 转发接口和 OTLP logs/traces/metrics 的接口可用率、投递成功率、P50/P95/P99/最大处理耗时、最近成功、失败、队列和丢弃；无请求窗口显示空闲/覆盖未知。
- 页面明确说明采集接口处理耗时不是工具执行耗时，并区分“接口可用”“实际请求投递成功”和“理论数据覆盖完整”。
- 关联情况提供精确、区间、推测、未关联筛选及分页明细列表。

### 诊断面板

- 按影响程度列出主要瓶颈和次要问题。
- 每条诊断包含结论、耗时占比、可信度和跳转到对应节点的操作。
- 没有足够证据时显示数据缺失说明，不生成确定性结论。
- 首版诊断完全由确定性规则引擎完成，不调用模型；规则使用阻塞关系、绝对阈值、当前范围分位数、失败与重试事件，并按影响时长排序。

## 指标补充口径

- 分析总览不再按“每轮原始耗时最大类别”统计主要瓶颈，改为跨轮次异常耗时贡献。
- 同类操作以当前筛选范围内的 P50 为基线；模型请求按传输方式分组，工具按工具名和规范化操作类型分组，禁止使用可能包含敏感内容的完整命令作为分组键。
- 单次操作只有同时比 P50 多至少 1 秒、且相对增幅至少 20% 时才计入异常；异常耗时等于实际耗时减 P50，类别贡献率等于该类别异常耗时总和除以全部异常耗时。
- 同类有效样本少于 5 个时显示样本不足；所有类别均未越过门槛时显示没有明显异常，不强行指定瓶颈。
- 单轮数据完整度由 Hook 骨架完整度、transcript 文件关联状态、JSONL 内容补齐率和 OTel 性能覆盖率四项等权计算。关联可信度单独展示，不混入完整度。

## Mock 数据模型

```text
MockSession
  id, title, project, model, source, status
  startedAt, durationMs, tokenUsage, dataCompleteness
  agentEvents[]
  performanceSpans[]
  alignments[]
  diagnoses[]

HookNode
  id, sessionId, turnId, toolUseId?, kind
  startedAt, endedAt?, derivedState, hookRaw
  timingPrecision, contentStatus, performanceStatus

JsonlSupplement
  sourceFileId, sessionMetaId, turnId?, callId?
  input?, output?, raw, adapterVersion

PerformanceSpan
  id, traceId, parentSpanId?, kind
  startedAt, durationMs, status, attributes

Alignment
  agentEventId, performanceSpanId
  level, evidence, timeDeltaMs
```

Mock 字段与未来 API 保持一致，避免后端接入时重写主要组件。

## 必备 Mock 场景

- 正常且数据完整的会话。
- TTFT 明显过长的会话。
- 多个不同工具并行执行。
- 两个同名工具并行且无法精确关联。
- 工具失败后重试。
- 长时间等待审批。
- 只有 JSONL 的原始记录检查场景；不得生成正式分析会话。
- 只有 OTel 的未绑定性能记录检查场景；不得生成正式分析会话。
- Hook tool_use_id 与 JSONL call_id 值相同、且格式适配器已验证的精确工具补齐场景。
- Hook 与 JSONL 标识不同，只能按同一 Turn、工具类型和时间重叠推测的场景。

所有数据必须为人工编写的虚构内容，统一使用类似 `/workspace/demo-project` 的路径和固定测试 ID。

## 视觉与交互约束

- 主要面向桌面浏览器，同时保证较窄窗口下仍可使用。
- 默认中文，时间按本地时区显示。
- Element Plus 是唯一通用组件体系。
- ECharts 是唯一图表体系，按需导入组件。
- 精确、区间、推测、未关联必须有一致的颜色、线型和文字标识，不能只依赖颜色区分。
- 键盘可聚焦主要操作，图表外提供可访问的节点列表。

## 原型验收清单

- 总览能筛选会话并定位最慢记录。
- 双层时间轴可同步缩放和平移。
- 并行工具以重叠泳道正确显示。
- 点击行为事件、性能 Span 和关联线均能查看详情。
- 用户能理解为何某些节点只属于推测关联。
- 本轮耗时摘要和异常贡献不会重复累计并行时间。
- 工具稳定约 4 秒、模型通常约 2 秒但少量抖动到 20 秒时，模型应成为主要异常贡献，工具异常贡献应接近零。
- 至少一个场景能明确诊断模型慢，一个场景能明确诊断工具慢。
- 没有 OTel 时不会伪造 TTFT 或推理细分。
- 页面中不存在真实账号、目录、密钥或会话内容。
- 顶部导航中的分析总览、实时会话和采集状态均可访问。
- 点击 Hook 时间轴的任一行为节点后，可以分别查看 Hook、JSONL 和 OTel 证据；缺失内容必须说明是尚未生成还是等待补齐。
- 采集状态页能判断 transcript 文件级关联是否有效，并显示每类失败原因。
- UNKNOWN 列表按结构指纹聚合；人工映射能展示 JSONPath 示例、预览匹配值、拒绝不支持语法，并只模拟重新标准化当前指纹。
- 页面明确区分 OTel 精确耗时、Hook 边界估算和 JSONL 时间戳估算。

V2 已于 2026-09-14 确认并冻结；正式前后端可以按该基线和技术设计的实施契约编码。后续产品或交互变化必须先形成需求并建立 V3，不得回写 V2。
